## Executive Summary

### Project Vision

构建一个**极简、高效、智能**的作文批改平台,通过统一登录降低门槛,双角色系统提升灵活性,AI 辅助提高批改效率。

### Target Users

**主要用户**: 教师(25-45岁)
- 核心需求: 高效批改作业
- 技术熟练度: 中等
- 使用场景: 办公室、家庭,使用电脑批改

**次要用户**: 学生(10-18岁)
- 核心需求: 简单提交作业
- 技术熟练度: 中高(熟悉手机操作)
- 使用场景: 家里、学校,使用手机或平板

**管理用户**: 管理员
- 核心需求: 指定教师权限
- 技术熟练度: 高
- 使用场景: 办公室,使用电脑

### Key Design Challenges

1. **如何平衡极简登录与信息收集?**
   - 方案: 登录后分步骤引导,而非登录前强制填写

2. **如何让双角色切换直观易懂?**
   - 方案: 独立的角色切换页面,清晰的视觉卡片

3. **如何让教师批改页面专注且高效?**
   - 方案: 内容优先布局(60%作文内容),AI 辅助不喧宾夺主

4. **如何让学生多格式提交简单易用?**
   - 方案: 默认文本输入,附件作为增强功能

### Design Opportunities

1. **渐进式披露(Progressive Disclosure)**
   - 登录时只要求手机号
   - 登录后逐步收集信息
   - 降低注册门槛

2. **上下文帮助(Contextual Help)**
   - 首登信息补全时显示"为什么需要这些信息"
   - 批改时显示学生历史背景

3. **智能默认(Smart Defaults)**
   - 记住上次活跃角色
   - 自动填写城市信息(基于 IP)

## Core User Experience

### Defining Experience

**核心体验**是一个**极简、渐进、智能**的作文批改平台:

- **极简**: 登录只需要手机号 + 验证码
- **渐进**: 信息分步骤收集,功能逐步开放
- **智能**: AI 辅助批改,自动建立学生长期记忆

### Platform Strategy

**主要平台**: 响应式 Web 应用
- **桌面端**: 教师主要使用,支持完整功能
- **移动端**: 学生主要使用,优化的触控体验
- **平板**: 两者兼顾,支持横屏和竖屏

**平台特定考虑**:
- 桌面端: 键盘快捷键(如 `Ctrl+S` 保存)
- 移动端: 语音输入按钮突出显示
- 平板: 手势操作(如滑动切换学生)

### Effortless Interactions

**应该感觉自然,无需思考的交互**:

1. **登录流程**
   - 输入手机号 → 自动聚焦到验证码输入框
   - 验证码输入到第 4 位 → 自动提交
   - 登录成功 → 自动跳转到对应页面

2. **教师批改流程**
   - 选择学生 → 自动显示学生历史背景
   - 输入分数 → 自动保存(每 30 秒)
   - 点击"提交" → 自动跳转到下一个学生

3. **学生提交流程**
   - 上传图片 → 自动 OCR 提取文字
   - 上传文档 → 自动提取文本
   - 输入文本 → 自动保存草稿

**关键成功时刻**:

1. **教师第一次使用语音输入**
   - "哇,语音转文字好准!"
   - 批改效率提升 3 倍

2. **学生第一次提交作业**
   - "上传图片后自动识别文字,太方便了!"
   - 提交时间从 10 分钟缩短到 2 分钟

3. **教师第一次看到学生历史背景**
   - "原来这个学生擅长描写,但结构需要改进!"
   - 批改更有针对性

4. **用户第一次切换角色**
   - "角色切换页面设计得真清晰!"
   - 一眼就能看到两个角色的区别

### Experience Principles

基于以上对话和 PRD,我总结出以下**核心体验原则**:

1. **极简优先(Simplicity First)**
   - 登录只需手机号 + 验证码
   - 移除所有不必要的元素
   - 减少认知负担

2. **渐进披露(Progressive Disclosure)**
   - 信息分步骤收集
   - 功能逐步开放
   - 避免一次性展示太多信息

3. **上下文智能(Contextual Intelligence)**
   - 显示学生历史背景
   - AI 辅助基于学生特点
   - 自动填写智能默认值

4. **高效流畅(Efficiency & Flow)**
   - 教师批改流程无中断
   - 自动保存,防止数据丢失
   - 键盘快捷键支持

**这些原则将指导所有设计决策。**

## Design System Strategy

### Selected Design System

**选择**: **Ant Design**

### Why Ant Design?

1. **中文 UI,教师友好**
   - 教师主要用户群体,中文 UI 降低学习成本
   - 组件语言符合中文使用习惯

2. **企业级,适合教育场景**
   - Table、Form 组件完善
   - 适合管理后台、工作台类应用
   - 稳定性高,维护成本低

3. **组件丰富,快速开发**
   - Steps 组件(用于多步骤向导)
   - Card 组件(用于角色切换卡片)
   - Input、Form 组件(用于登录和信息补全)
   - 丰富的图标库

4. **文档完善,社区活跃**
   - 中文文档详尽
   - 社区案例丰富
   - 问题容易解决

### Responsive Design

**断点策略**:

```css
/* 移动端 */
@media (max-width: 576px) {
  /* 单列布局 */
  .container { max-width: 100%; }

/* 平板 */
@media (min-width: 577px) and (max-width: 992px) {
  /* 两列布局 */
  .container { max-width: 90%; }
  .grading-page { flex-direction: row; }

/* 桌面端 */
@media (min-width: 993px) {
  /* 三列布局 */
  .container { max-width: 1200px; }

}
```

**布局调整**:

| 页面 | 移动端 | 平板 | 桌面端 |
|------|--------|------|--------|
| 登录页 | 单列,居中 | 单列,居中 | 居中卡片 |
| 角色切换 | 上下排列 | 左右排列 | 左右排列 |
| 批改页面 | 单列(作文优先) | 两列 | 三列(学生列表 + 作文 + AI) |
| 学生提交 | 单列 | 单列 | 单列 |

**组件行为**:

- **学生列表**: 移动端隐藏到抽屉,平板/桌面显示侧边栏
- **AI 面板**: 移动端折叠到底部,平板/桌面显示右侧
- **表单**: 移动端全宽,平板/桌面居中

### Accessibility

**WCAG AA 合规**:

1. **键盘导航**
   - 所有交互元素可聚焦
   - `Tab` 键顺序合理
   - `Enter` / `Space` 激活按钮

2. **ARIA 标签**
   - 所有图标有 `aria-label`
   - 表单字段有关联的 `label`
   - 错误消息有 `role="alert"`

3. **色彩对比度**
   - 文本对比度 ≥ 4.5:1
   - 大文本(18px+)对比度 ≥ 3:1
   - 非文本内容(图标)对比度 ≥ 3:1

4. **焦点管理**
   - 焦点可见(`outline: 2px solid #1890ff`)
   - Modal 打开时焦点移到 Modal
   - Modal 关闭时焦点返回触发元素

5. **屏幕阅读器支持**
   - 语义化 HTML(`<nav>`, `<main>`, `<article>`)
   - `role` 属性正确使用
   - 动态更新使用 `aria-live`

**焦点管理示例**:

```typescript
// 角色切换页面
const RoleSwitchPage = () => {
  const roleCardsRef = useRef<HTMLDivElement>(null);

  // 页面加载时,聚焦到当前角色卡片
  useEffect(() => {
    const currentRoleCard = roleCardsRef.current?.querySelector(`[data-role="${activeRole}"]`);
    currentRoleCard?.focus();
  }, [activeRole]);

  return (
    <div>
      <RoleCard
        ref={roleCardsRef}
        data-role="student"
        tabIndex={0}
        aria-current={activeRole === 'student' ? 'true' : undefined}
        onKeyDown={(e) => {
          if (e.key === 'Enter' || e.key === ' ') {
            switchRole('student');
          }
        }}
      >
        🎓 学生
      </RoleCard>
    </div>
  );
};
```
